# Contributing

## Running the checks

Every check is a make target. The full set that needs no network:

```sh
make all
```

which runs, in order:

| Target | What it does |
| --- | --- |
| `scan` | fails if site identity or key material reached the tree |
| `lint` | ShellCheck, `perl -cw`, and Perl::Critic |
| `test` | the suite, against a fixture site |
| `build` | packages the module as a `.wbm.gz` |
| `verify` | checks the package the way Webmin's installer does |

Two further targets need network access and are not part of `all`:

```sh
make apicheck      # every Webmin function the module calls exists in WEBMIN_REF
make e2e           # init against a real easy-rsa, and apicheck
make e2e-matrix    # e2e against each release in EASYRSA_REFS
```

Run `make e2e` before trusting any change to `vpn-server init`. The fixture
cannot prove what the real tool does; see "Test doubles" below.

Before pushing:

```sh
make preflight
```

## Dependencies

Dependencies install into the working tree rather than the system, so a
checkout is self-contained and a CI runner needs no privileges:

| Dependency | Location | Pinned by |
| --- | --- | --- |
| Perl::Critic | `local/` | `cpanfile` |
| easy-rsa | `.easyrsa/` | `EASYRSA_REF` |
| Webmin | `.webmin/` | `WEBMIN_REF` |

`make perldeps` installs the first; the other two are fetched by the targets
that need them. `make distclean` removes all three.

## Coding standards

- Shell is `bash`, ShellCheck-clean with no unexplained `disable` directives.
- Perl is `perl -cw` and Perl::Critic clean at severity 4. Module files use
  `use strict` and `use warnings`, and declare Webmin's package globals with
  `our`.
- Python follows PEP 8, 79 columns.
- Comments explain why something is the way it is. What the code does should be
  readable from the code.

## Architecture rule

The module contains no OpenVPN logic. It renders what `vpn-client list --json`
and `vpn-server status --json` report, and calls the tools for anything that
changes state. Every path the interface can take is therefore a path that can
also be taken, and tested, from a shell.

When the interface needs something the tools cannot do, extend the tools.

## Test doubles

The suite builds a throwaway site with a **real** EC PKI generated by
`openssl`, so certificate handling runs against real certificates. Three
dependencies are faked, each for a reason that cannot be worked around:

| Faked | Why |
| --- | --- |
| `systemctl` | no init system in a container |
| `id` | the checks must give the same result privileged or not |
| `easyrsa` | a full easy-rsa install is not a test dependency |

**A mock that supplies the value under test validates nothing about it.** The
fixture's fake `easyrsa` was once handed its curve by the fixture, so it
produced EC certificates regardless of what the code requested — while the code
was in fact inheriting easy-rsa's RSA default. The mocked suite was green
throughout. Assertions about what the real tool does belong in `make e2e`,
which runs against a genuine easy-rsa checkout.

The same limit applies to `tests/stubs/WebminCore.pm`. It exists so Webmin
modules can be syntax- and policy-checked on a machine without Webmin, and it
deliberately implements nothing. It proves compilation, never behaviour;
`make apicheck` proves the functions exist in a given Webmin release, and only
a browser proves a page renders.

## Repository hygiene

No host name, network address, path or key material belonging to a real
installation may enter this repository. `make scan` enforces this structurally:
it rejects any fully qualified domain name outside the RFC 2606 documentation
domains, any address outside a short declared list, Windows-style paths, and
private key headers. Private addresses are not exempt — RFC 1918 space
describes the topology of a specific site as surely as a public address does.

Two limits are worth knowing. The `.sh`, `.pl` and `.info` suffixes are
excluded from the host name rule because they collide with filenames in this
repository, so a host under those TLDs would pass. And a site codename is an
ordinary word rather than a structural pattern; no scanner can catch that, and
a denylist would have to contain the word it exists to keep out. Both are
matters of convention and review.

`make preflight` extends the scan to every unpushed commit and to commit
messages, because a push publishes history, not just the checkout.

## Commits

Describe the reasoning, not the diff: what was wrong, what changed, and why
that is the right place for the change. Where a defect was found by a specific
check, say which — that is what tells the next reader whether the check is
worth keeping.
